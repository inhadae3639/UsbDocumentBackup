# Google Drive 연결 설정

> **현재 상태:** Drive 연동은 구현·모의 검증이 끝났고, 실제 계정 인증만 남았다.
> 연결하지 않아도 PC 백업과 복원은 그대로 동작하며, 업로드는 대기 상태로 쌓인다.

로그인과 권한 동의는 **반드시 사용자가 직접** 해야 한다. 비밀번호나 인증 코드를 대화창이나
소스에 붙여 넣지 않는다.

## 1. Google Cloud 프로젝트 준비

1. https://console.cloud.google.com 에서 프로젝트를 만든다.
2. **API 및 서비스 → 라이브러리**에서 **Google Drive API**를 사용 설정한다.
3. **API 및 서비스 → OAuth 동의 화면**을 설정한다.
   - 사용자 유형: 개인 Gmail 계정이면 **외부(External)**, Google Workspace 계정이면 **내부(Internal)**.
   - 앱 이름, 지원 이메일, 개발자 연락처를 채운다.
   - 범위(scope)에 `https://www.googleapis.com/auth/drive.file`을 추가한다.
     **Drive 전체 접근 권한은 추가하지 않는다.** 이 앱이 만든 파일만 다루면 충분하다.
4. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **데스크톱 앱 (Desktop app)**
   - 만든 뒤 **JSON 다운로드**를 눌러 `client_secret_*.json`을 저장한다.

### ⚠ 자주 하는 실수: '서비스 계정 키'를 받는 것

같은 화면에서 **서비스 계정**도 만들 수 있고 키 JSON을 받을 수 있는데, **이 앱에는 쓸 수 없다.**

| | 서비스 계정 키 | OAuth 데스크톱 클라이언트 |
|---|---|---|
| JSON 최상위 키 | `"type": "service_account"` | `"installed"` |
| 정체 | 로봇 계정 (사람이 아님) | 내 계정으로 로그인할 앱의 신분증 |
| 업로드 위치 | 로봇 계정 소유. **내 드라이브에 안 보임** | **내 드라이브** |
| 저장 용량 | 자체 용량 없음 → 업로드가 용량 초과로 실패 | 내 Drive 용량 사용 |
| 브라우저 로그인 | 없음 | 있음 (최초 1회) |

받은 파일을 열어 **`"installed"` 가 있으면 맞는 파일**, `"type": "service_account"` 이면 틀린 파일이다.
앱은 틀린 파일을 거부하고 이유를 창으로 알려준다.

**서비스 계정 키를 이미 받았다면 폐기하라.** 그 JSON에는 개인 키 전문이 들어 있어, 유출되면 누구나
그 계정으로 API를 호출할 수 있다. Google Cloud Console → IAM 및 관리자 → 서비스 계정 → 해당 계정 →
**키** 탭에서 해당 키를 삭제하고, 내려받은 파일도 지운다.

## 2. 토큰 만료 문제 (중요)

**외부(External)** 유형이면서 게시 상태가 **테스트(Testing)** 인 프로젝트는, 발급된 **갱신 토큰이
7일 후 만료**된다. 이 상태로 두면 매주 다시 로그인해야 한다.

선택지는 둘이다.

- **테스트 사용자로 계속 사용:** 7일마다 재연결. 잠깐 써 볼 때만 적합.
- **프로덕션으로 게시:** 갱신 토큰이 7일 제한을 받지 않는다. **OAuth 동의 화면 → 앱 게시**.
  - `drive.file`은 민감하지 않은 범위로 분류되므로, 보통 별도 보안 심사 없이 게시할 수 있다.
  - 다만 **게시했다고 모든 검증·관리자 정책이 자동으로 해결되는 것은 아니다.** 특히 학교나 회사
    Workspace 계정은 관리자가 서드파티 앱 접근을 막아 둘 수 있다. 이때는 관리자에게 요청해야 한다.

장기간 쓸 계획이면 **연결 전에** 게시 상태와 대상 사용자, 계정 종류(개인 / Workspace)를 먼저 확인하는 편이 낫다.

## 2-A. 여러 PC에서 쓸 때

- `client_secret.json` 은 PC 간에 복사해도 된다. 비밀이긴 하지만 사용자별 토큰은 아니다.
- **갱신 토큰은 복사해도 소용없다.** DPAPI로 현재 Windows 사용자·현재 PC 기준으로 암호화되어 있어
  다른 PC에서는 복호화되지 않는다. PC마다 한 번씩 '연결'을 눌러 인증해야 한다.
- 같은 Google 계정에 연결하면 모든 PC가 같은 `USB Document Backups` 폴더를 쓴다.

## 2-B. 테스트 사용자 등록 (테스트 상태로 쓸 경우 필수)

게시 상태가 **테스트 중**이면, 등록된 테스트 사용자만 로그인할 수 있다. 본인 계정도 예외가 아니다.
등록하지 않으면 로그인 화면에서 `403 오류: access_denied` 와 함께
"앱은 현재 테스트 중이며 개발자가 승인한 테스터만 앱에 액세스할 수 있습니다" 가 뜬다.

**Google 인증 플랫폼 → 대상 → 맨 아래 '테스트 사용자' → + Add users** 에서 로그인할 계정을 추가한다.

프로덕션으로 게시하면 이 목록은 더 이상 필요 없다.

## 3. 앱에서 연결

1. 트레이 → **설정** → Google 연결 → **클라이언트 설정 파일 선택**에서 1번에서 받은
   `client_secret_*.json`을 고른다.
2. **연결** 버튼을 누르면 그때 기본 브라우저가 열린다.
   토큰이 만료돼도 **브라우저가 저절로 열리지는 않는다.** 발표 중에 창이 튀어나오지 않게 하기 위해서다.
3. 브라우저에서 계정을 고르고 권한에 동의한다.
4. 연결되면 Drive에 `USB Document Backups` 폴더가 만들어지고, 이후 업로드는 전부 그 아래로 간다.

갱신 토큰은 Windows DPAPI로 **현재 사용자 범위**로 암호화해 `credentials/`에 저장한다.
설정 파일·로그·SQLite에 평문 토큰이 들어가지 않는다. 다른 Windows 사용자 계정이나 다른 PC로
파일을 복사해도 복호화되지 않는다.

## 4. Drive에 저장되는 형태

- 업로드 원본은 USB가 아니라 **검증이 끝난 PC 보관본**이다.
- 원본 `.ppt` / `.pptx` 형식 그대로 올린다. Google Slides로 변환하지 않는다.
- 각 버전이 **독립된 파일**이다. 이전 버전을 덮어쓰지 않는다.
- 원본 폴더 경로·장치 표시명·백업 시각을 파일/폴더 이름과 메타데이터에 남겨 웹에서도 식별할 수 있게 한다.
- 앱에는 **원격 파일을 자동 삭제하는 경로가 없다.**

## 4-A. 연결 실패 시 오류별 대처

앱은 Google이 돌려준 오류 코드를 그대로 보여주지 않고 무엇을 해야 하는지 창으로 안내한다.

| 오류 | 원인 | 대처 |
|---|---|---|
| `access_denied` | 테스트 상태인데 테스트 사용자 미등록. 또는 동의 화면에서 '취소'를 누름 | 2-B 참고 |
| `admin_policy_enforced` | 학교/회사 관리자가 서드파티 앱을 차단 | 개인 계정으로 연결하거나 관리자에게 요청 |
| `invalid_client` | 클라이언트를 지우고 다시 만든 뒤 옛 JSON을 쓰는 중 | 새 JSON을 다시 가져오기 |
| `invalid_grant` | 권한 철회 또는 테스트 상태의 7일 만료 | 다시 연결 |

## 5. 연결이 끊겼을 때

토큰 철회, 만료, 조직 관리자 정책 변경이 생기면 업로드만 "연결 필요" 상태로 바뀐다.
**PC 백업은 계속된다.** 이 상태에서는 영구 등급 파일의 로컬 사본이 7일이 지나도 삭제되지 않는다.

재연결할 때 처음과 다른 계정을 고르면 확인을 거친다. 기존 대기 파일이 조용히 다른 계정으로 올라가지 않는다.

## 6. 하지 않는 것

- 프로그램 설치 전에 이미 영구 삭제된 파일의 디스크 복구
- 다중 Google 계정, 공유 드라이브, 다른 클라우드
- Drive에서 사용자가 직접 백업을 지우는 것까지 막는 기능 — 이 앱은 그런 제품이 아니다
