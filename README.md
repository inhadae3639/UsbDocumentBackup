# USB 문서 자동 백업

Windows 로그인 후 트레이에 상주하면서, USB에 연결된 발표 자료를 PC에 먼저 백업하는 프로그램.
설계 문서: `USB-Drive-Backup-Implementation-Plan.md` (2026-09-09), 이후 사용자 요구로 **보관 등급**이 추가됨.

## 무엇을 백업하는가

대상은 **`.ppt` / `.pptx` 뿐이다.** PDF는 백업하지 않는다 — 잠금 파일도 최근 문서 기록도 없어
영구 등급이 될 수 없는데, 실제 USB 한 개에서 511개 7 GB를 차지했기 때문이다.

| 등급 | 대상 | 위치 | Drive | 로컬 삭제 |
|---|---|---|---|---|
| **영구 (Retained)** | **이 PC에서 연 발표자료** — 저장 위치 무관 | `archive/retained/` | 업로드함 | 7일 경과 **그리고** 업로드 완료 확인 후 |
| **임시 (Temporary)** | USB에 있으나 연 적 없는 `.ppt`/`.pptx` | `archive/temp/` | 안 올림 | 7일 경과 |

두 등급을 **물리적으로 다른 폴더**에 두는 이유는, 나이만 보는 임시 정리 루틴이 아직 업로드되지 않은
발표자료에 절대 닿을 수 없게 하기 위해서다.

### "열었다"는 판정 — 두 가지 신호

**1. PowerPoint 최근 문서 목록 (주 신호)**

`HKCU\Software\Microsoft\Office\{버전}\PowerPoint\File MRU` 와 `User MRU\{계정}\File MRU` 를 읽는다.
값의 형식은 `[F…][T<FILETIME 16진>][O…]*<전체 경로>` 이며, 여기서 전체 경로와 연 시각을 얻는다.

이 방식의 두 가지 이점:

- **저장 위치 무관.** USB든 바탕화면이든 OneDrive 동기화 폴더든 네트워크 공유든 절대 경로가 그대로 들어 있다.
- **소급 포착.** 프로그램이 꺼져 있던 동안 열었다 닫은 자료도 목록에 남아 있어 나중에 잡힌다.

한계: 목록은 계정당 약 50개로 제한되고, 그룹 정책으로 꺼질 수 있으며, SharePoint/OneDrive 웹에서 바로
연 문서는 로컬 파일이 없어 건너뛴다. Office에 로그인한 계정마다 키가 따로 있어 전부 읽는다.

**2. Office 소유자 파일 (보조 신호)**

문서를 여는 동안 같은 폴더에 생기는 `~$` 파일을 감시해 즉시 반응한다. 이름 규칙이 두 가지라
(짧은 이름은 그대로, 긴 이름은 앞 두 글자가 접두사로 대체됨) 후보가 둘 이상이면 **자동 확정하지 않고**
문제 기록에만 남긴다 — 열지 않은 자료가 Drive로 올라가는 것을 막기 위해서다. 확정은 최근 문서 목록이 한다.

### 언제부터 감시하나

**설치(첫 실행) 시점부터입니다.** PowerPoint 최근 문서 목록에는 계정당 최대 50개, 몇 달 치가 남아
있어서, 그대로 두면 설치하자마자 과거 자료가 전부 Drive로 올라갑니다. 그래서 첫 실행 시각을
`settings.json`의 `MonitorSinceUtc`에 기록하고, 그 이후에 연 자료만 자동 대상으로 삼습니다.

이전 자료가 필요하면 **설정 → 감시 시작 → "이전 발표자료도 백업..."** 을 누릅니다.
몇 건이 대상인지 먼저 알려주고, 확인하면 **그 한 번만** 과거분을 처리합니다.

두 신호 모두 DB의 `opened_documents`에 영속 기록되므로 문서를 닫거나 프로그램을 재시작해도 유지된다.
이미 임시 등급으로 보관 중이던 자료가 나중에 "열림"으로 확인되면 **원본 재읽기 없이** 등급만 승격되고
업로드 큐에 들어간다.

### 7일 후 로컬 삭제의 의미

영구 등급 파일은 **Drive 업로드가 완료로 확인된 뒤에만** 로컬 사본이 정리된다. 대기·업로드 중·조치 필요
상태면 몇 달이 지나도 지우지 않는다. 정리된 뒤에도 DB 행은 남으므로 SHA-256과 Drive 파일 ID로
Drive에서 내려받아 복원할 수 있다 — 단, 그 시점부터 **복원이 Drive 단독 의존**이 된다.

## 보관 위치

```
%LOCALAPPDATA%\UsbDocumentBackup\
  settings.json          설정 (UTF-8)
  state.db               SQLite 상태 (장치·백업·업로드 큐·열린 문서 기록·문제 기록)
  credentials/           현재 Windows 사용자로 암호화된 인증 정보
  logs/                  크기 제한 로그 (토큰·세션 URL 미기록)
  archive/
    retained/<장치>/<백업ID>/<원래 파일명>
    temp/<장치>/<백업ID>/<원래 파일명>
```

`archive`만 설정에서 다른 로컬 디스크로 옮길 수 있다. 상태 DB와 인증 정보는 항상 사용자 앱 데이터에 남는다.
이미 보관 중인 데이터의 자동 경로 이전은 없다.

## 원본 보호

원본은 읽기 전용으로만 접근한다. 이름 변경·이동·삭제·내용 수정을 하지 않으며, USB의 원본을 지워도
그 삭제를 보관본에 전파하지 않는다. 읽을 때 `FileShare.ReadWrite | Delete`로 열어 PowerPoint의 쓰기를
막지 않고, 대신 복사 전후의 크기·수정 시각을 비교해 도중에 바뀐 파일은 완료로 처리하지 않는다.

## 무결성

파일 하나의 처리 순서:

1. 크기·수정 시각이 안정될 때까지 잠시 대기
2. `<대상>.partial`로 스트리밍 복사하면서 SHA-256 계산 (읽기 속도 제한 적용)
3. 복사 후 원본 크기·수정 시각 재확인 → 바뀌었으면 폐기
4. `.partial`을 **디스크에서 다시 읽어** SHA-256 재계산 → 불일치하면 폐기
5. 직전 버전과 해시가 같으면 새 버전을 만들지 않음 (등급 승격만 필요하면 승격)
6. DB에 `Pending` 행 기록 → `.partial`을 최종 이름으로 rename → `Complete` + 업로드 큐 등록

파일시스템과 DB는 원자적이지 않으므로, 시작할 때 `Pending` 행을 실제 디스크 상태와 대조한다.
rename까지 끝났고 해시가 맞으면 완료 처리하고, 아니면 행과 파일을 함께 버린다. 미완료 파일이
정상 백업으로 표시되는 일은 없다.

```bash
dotnet build UsbDocumentBackup.slnx -c Release
```

```bash
dotnet test tests/UsbDocumentBackup.Tests/UsbDocumentBackup.Tests.csproj
```

## 배포

런타임을 포함한 단일 실행 파일을 만든다. **대상 PC에는 .NET을 설치하지 않아도 된다.**

```bash
dotnet publish src/UsbDocumentBackup/UsbDocumentBackup.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o artifacts/publish
```

`artifacts/publish/UsbDocumentBackup.exe` (약 105 MB) 하나를 대상 PC의 **고정된 폴더**에 두고 실행한다.
예: `C:\Program Files\UsbDocumentBackup\` 또는 `%LOCALAPPDATA%\Programs\UsbDocumentBackup\`.

### 자동 실행 등록 / 해제

트레이 → **설정** → "Windows 로그인 시 자동 실행" 체크. 등록은 현재 사용자 범위
(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`)에만 이뤄지고 관리자 권한이 필요 없다.

빌드 출력 폴더(`bin\Debug`, `bin\Release`)나 임시 폴더에서 실행 중이면 **자동 실행 등록이 거부된다.**
사라질 경로가 시작 프로그램에 남는 것을 막기 위한 의도된 동작이다.

제거하려면 체크를 해제하거나 위 레지스트리 값을 지운다. **프로그램을 지워도 백업은 지워지지 않는다.**
보관본을 없애려면 `%LOCALAPPDATA%\UsbDocumentBackup\`을 직접 삭제해야 한다.

## 사용

트레이 아이콘 메뉴: 상태 열기 / 백업 폴더 열기 / 일시정지·재개 / 설정 / 진단 정보 저장 / 종료.
발표를 방해하지 않도록 콘솔·진행창·풍선 알림을 띄우지 않고 포커스를 가져가지 않는다.

### 복원

상태 창에서 파일 이름이나 원본 경로로 검색 → 버전 선택 → **선택 버전 복원**. 복원 폴더를 고르면
복사 후 SHA-256을 검증한다. 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 `이름 (2).pptx`로 저장한다.

## 성능

USB 읽기는 기본 5 MiB/s, 업로드는 2 MiB/s로 제한한다(설정에서 변경 가능). 원본을 읽는 **모든** 경로가
같은 제한을 통과하므로 해시 계산이 제한을 우회하는 구멍이 없다.

제한이 낮을수록 발표 중 간섭은 줄지만 복사 완료까지 걸리는 시간이 길어지고, 그동안 USB가 뽑히면
그 파일은 미완료로 남아 다음에 재시도된다. 기본값은 실제 장치로 측정한 뒤 조정해야 한다.

**"발표에 전혀 영향이 없다"고 보장하지 않는다.**

## 문제가 생겼을 때

**설정 → 진단 정보 저장...** 을 누르면 바탕화면에 진단 파일이 저장되고 열립니다.
명령줄에서 `UsbDocumentBackup.exe --diagnose` 로도 같은 일을 할 수 있습니다.

연결 상태, 이 PC에 토큰이 있는지, 백업·업로드 건수, 업로드 실패 사유, 최근 경고가 담깁니다.
**비밀번호·토큰·client secret은 포함되지 않습니다.**

가장 흔한 원인은 **그 PC에서 Google 연결을 하지 않은 것**입니다. 토큰은 Windows DPAPI로
PC·사용자 계정에 묶여 암호화되므로, 다른 PC에서 연결했어도 적용되지 않습니다. PC마다 한 번씩
설정에서 '연결'을 눌러야 합니다. 그동안 업로드는 대기 상태로 쌓이고 로컬 사본은 삭제되지 않습니다.
